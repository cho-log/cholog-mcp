# 리뷰 대화 도구 최종 검증

- 날짜: 2026-11-18
- 목적: [이슈 #8](https://github.com/cho-log/cholog-mcp/issues/8)의 최종 구현 범위와 현재 실행 가능한 검증 절차를 남긴다.
- 코드 기준: `feat/get-review-context`의 `1e393805636c6ea6d1e180050df943de8f5fed59`. 이번 문서 정리에서는 기능 코드·테스트·워크플로를 변경하지 않았다.

## 최종 구현 범위

- `get_review_context`는 미션·작성자·PR 생성일로 선택한 PR과 리뷰어 댓글·작성자 답글의 원문, 링크, 시각을 제공한다. 태그 없는 댓글도 포함하며, 주제 선정은 도구 설명의 기준을 읽은 사용자 에이전트가 담당한다.
- 리뷰 답글은 같은 미션·PR의 review 댓글에서 원본 부모 ID로 연결한다. 부모 누락을 표시하고, 일반 PR 대화는 시간순으로 제공하며 인접 댓글을 답글로 연결하지 않는다.
- 대화 단위로 페이지를 나누고 큰 대화는 댓글 경계에서 분할해 부분 범위와 다음 커서를 표시한다. 같은 요청 범위와 DB 상태에서 누락·중복 없이 이어 읽으며 범위나 자료가 달라진 커서는 거절한다.
- 댓글 내부 키와 GitHub 원본 ID를 분리해 review/issue ID 충돌을 처리한다. 서버는 DB를 읽기만 하며, 기존 `get_repeated_feedback`의 집계·선정·응답 계약을 유지한다. 세부 입력·응답·제한은 [도구 명세](../tool-spec.md)를 따른다.

## DB 재생성과 배포

[배포·DB 스키마 관리 결정](../decisions.md)에 따라 수집 → 최신 스키마의 새 DB 생성·적재 → 분류 → 검증 후 코드와 DB를 같은 이미지에 포함한다. 직전 DB는 비교 검증에만 사용한다. 현재 워크플로는 이미지 빌드까지 수행하며 실제 AWS 자동 배포 연결은 후속 작업이다.

기존 DB의 스키마 변환을 지원하지 않는 이유는 배포마다 DB를 재생성하는 구조다. 원본과 분류 코드·사전·설정이 확보되어 있어야 한다. 보관한 원본 JSON에 답글 부모 정보가 있으면 재적재로 보완하고, 없거나 수집 완전성을 확인할 수 없으면 재수집한다. 배포된 HTTP 서비스 사용자는 DB 관리 작업을 하지 않으며, 로컬 개발자는 필요하면 새 DB를 생성·검증하고 `CHOLOG_DB_PATH`를 교체한다. 재검토 조건과 준비 절차는 [결정](../decisions.md)과 [새 DB 생성 명세](../tool-spec.md#새-db-생성과-http-배포)에 있다.

## 실행한 검증

합성 fixture와 임시 SQLite를 사용했다. 실제 수집 원본·운영 DB·MCP 연결 설정을 변경하지 않았고, 학생 코드를 실행하지 않았다.

| 명령 | 결과 |
|---|---|
| `uv sync --locked` | 성공 |
| 아래 최소 확인 절차의 `uv run pytest` 두 테스트 | 2 passed |
| `uv run pytest` | 144 passed |
| `uv run python -m pipeline --help` | 성공. `fetch/load/tag/verify/check`와 필수 미션 인자 확인 |
| `git diff --check` | 통과 |

전체 회귀에서 작성자 답글·필터·태그 없는 댓글·부모 누락·원문 보존·페이지 경계·커서 오류·식별자 충돌·최신 스키마 제약·재적재 원자성과 기존 도구를 검증했다. 변경 문서의 내부 링크·앵커와 참조 파일 경로도 확인했다.

## 최소 확인 절차

저장소 루트에서 실행한다. 테스트 fixture가 임시 DB 경로를 설정하므로 실제 `data/` 준비나 MCP 연결 설정 변경은 필요 없다.

```bash
uv sync --locked
uv run pytest \
  tests/test_server.py::test_실제_stdio_프로세스에서_두_도구를_호출한다 \
  tests/test_http.py::test_HTTP로_리뷰_문맥을_호출한다
```

첫 테스트는 실제 stdio 서버 프로세스를 띄워 두 도구의 등록·설명을 확인하고 모두 호출한다. 두 번째는 HTTP 앱의 TestClient로 `/mcp`에 새 도구를 호출한다. 외부에 배포된 HTTP 서비스에 접속하는 검증은 아니다. 전체 회귀는 `uv run pytest`로 실행한다.

## 검증하지 않은 항목

- 이번 검증에서 실제 자연어 에이전트의 도구 선택·이어 읽기·근거 링크 표시와 추천 유용성을 직접 확인하지 않았다. 자동 테스트 통과가 추천의 유용성을 뜻하지 않는다.
- 실제 스터디 준비·모임 사용과 학습 효과, 실제 데이터에서의 응답 크기·지연·메모리 사용은 검증하지 않았다. 조회는 요청 범위의 자료를 메모리에 구성하므로 큰 자료의 성능 측정이 필요하다.
- 실제 GitHub 재수집·실데이터 DB 재생성·Docker 이미지 빌드·배포 워크플로 실행·AWS 배포는 이번 검증에서 수행하지 않았다.
