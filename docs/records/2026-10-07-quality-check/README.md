# 품질 확인: 맥락 없는 세션에서 써 보기

- 일자: 2026-10-07
- 목적: 첫 도구(`get_repeated_feedback`)가 실제로 쓸 만한 답을 만드는지 확인한다

> 기록 문서다. 작성한 날의 내용 그대로이며 이후에 갱신하지 않는다. 지금의 기준은 [도구 명세](../../tool-spec.md)다.

## 무엇을 확인하려 했나

| 질문 | 왜 중요한가 |
|---|---|
| 서버를 모르는 AI가 도구를 스스로 골라 쓰는가 | 만든 사람이 있는 세션에서만 되면 의미가 없다 |
| 리뷰를 전부 주지 않고 집계와 대표 리뷰만 줘도 쓸 만한 답이 나오는가 | 토큰을 아끼려고 정한 방식이 답의 질을 깎지 않는지 봐야 한다 |
| 리드가 이미 아는 수준을 넘는가 | 넘지 못하면 만들 이유가 없다 |

## 방법

- 서버를 Claude Code에 등록한 뒤, 이 프로젝트와 상관없는 폴더에서 새 세션을 열었다.
- 도구 이름이나 사용법은 알려주지 않고 질문만 했다.
- 답을 받은 뒤, 같은 세션에 "어떤 과정으로 답했는지"를 정리하게 했다.
- 단, 작성자의 개인 설정(한국어 응답, 단계 표시 등)은 적용된 상태였다. 답변 끝의 "로드맵"은 그 영향이다.

## 질문 두 개

| | 질문 | 범위 | 답변 | 과정 |
|---|---|---|---|---|
| 1 | "자동차 경주 미션 끝나고 리뷰 수업 자료를 만들려고 해. 우리 스터디원들이 공통으로 지적받은 게 뭐야?" (GitHub ID 10개와 함께) | 스터디원 10명 | [답변](racingcar-feedback-answer.md) | [과정](racingcar-feedback-process.md) |
| 2 | "초록스터디 자동차경주에서 사람들이 제일 헷갈려하는게 뭐야?" | 미션 전체 | [답변](racingcar-confusing-answer.md) | [과정](racingcar-confusing-process.md) |

1번은 이 도구가 겨냥한 질문이고, 2번은 겨냥하지 않은 질문이다.

## 결과

**통과로 판단했다.** 작성자(리드 경험자)의 평가는 "이 정도면 만족스럽다"였다.

| 확인하려던 것 | 결과 |
|---|---|
| 도구를 스스로 고르는가 | 두 번 다 도구 이름과 서버 안내문만 보고 골랐다. 도구 호출은 각각 2번(스키마 조회, 실행)이었다 |
| 도구 설명대로 쓰는가 | 1번은 "미션이 끝난 뒤, 스터디원"을 보고 `authors`를 채웠고, 2번은 "사람들"이라 비웠다 |
| 지시를 답에 반영하는가 | 데이터 기준 시각, "대략적인 값", 주제가 붙지 않은 리뷰 수, 원문 링크를 모두 밝혔다 |
| 리드가 아는 수준을 넘는가 | 1번에서 "우리 스터디가 전체보다 유독 많이 지적받은 주제" 3개가 나왔다. 혼자서는 얻기 어려운 정보다 |

## 알게 된 것

### 1번 질문에서

- AI가 `overall_pr_ratio`의 뜻과 `pr_ratio`의 분모를 **추측**했다. 맞히긴 했지만 응답에 설명이 없었다.
- 대표 리뷰에 PR 작성자가 없어서 "누가 무엇을 지적받았는지"를 나누지 못했다.
- 같은 리뷰가 두 주제의 대표로 나왔다.
- AI가 기본값(주제 8개, 리뷰 2개)을 10개, 3개로 올려서 불렀다. 수업 자료용으로는 기본값이 작을 수 있다.

### 2번 질문에서

- **"헷갈려하는 것"을 직접 재는 도구가 없어서, AI가 "반복 지적받은 것"을 대신 썼다.** 그리고 그 한계를 답변 첫머리에 스스로 밝혔다. 스터디원의 질문을 보여주는 도구가 따로 필요하다는 근거다.
- **세부 지적이 한 주제에만 있어서 답이 그쪽으로 기울었다.** PR 수로는 4위인 난수 분리를 AI가 1순위로 꼽았는데, 근거 중 하나가 "세부 유형이 여러 갈래"였다. 다른 주제에는 세부 지적을 채우지 않았을 뿐이다. AI도 이 편향을 과정 문서에 적었다.
- 상위 4개 주제(네이밍, 예외 처리, 책임 분리, 난수 분리)가 거의 동률이었다. 어느 미션에서나 나오는 주제가 상위를 채우면 순위가 말해주는 것이 적다.

### 공통

- 주제가 붙지 않은 리뷰(스터디 범위 246개 중 117개, 전체 2,940개 중 1,231개)는 어느 답에도 반영되지 않았다.
- AI가 GitHub 원문을 열어 보지는 않았다. 인용과 링크는 모두 도구의 응답에서 나왔다.

## 반영한 것

| 알게 된 것 | 조치 |
|---|---|
| 필드의 뜻을 추측함 | 도구 설명에 "돌려주는 값 읽는 법"을 추가 |
| PR 작성자가 없음 | 대표 리뷰에 `author` 추가 |

두 질문 모두 이 조치 이전의 서버로 시험했다. 그래서 기록 속 응답에는 `author`가 없다.

## 남은 것

[도구 명세](../../tool-spec.md)의 "아직 정하지 않은 것"과 "나머지 도구"로 이어진다.

- 같은 리뷰가 여러 주제의 대표로 나오는 문제
- 스터디원의 질문을 보여주는 도구 (`get_learner_questions`)
- 다른 주제의 세부 지적 채우기
- 어느 미션에서나 나오는 주제 다루기
- 주제가 붙지 않는 리뷰 줄이기 (분류 개선)
