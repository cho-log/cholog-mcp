## 발견하고 수정한 결함

### P2: 열 이름만으로 중간 스키마를 전환 완료로 승인

`github_id`와 `in_reply_to_id`만 ALTER로 추가한 DB도 `create_schema`, `migrate_schema`, 새 조회가 받아들였다. 원본 ID의 NOT NULL과 유일성 제약이 없는 상태에서 적재하면 중복 댓글을 거절하지 못하고, 조회 시 원본 ID를 키로 만든 대화 맵에서 댓글이 덮일 수 있다. 부분 유일 인덱스나 PR까지 포함한 유일 인덱스도 같은 계약을 보장하지 못한다.

명세를 보완한 뒤 실패 테스트를 작성했다. `db.has_comment_identity_constraints`에서 내부 rowid 별칭 정수 기본키, 원본 정수 ID의 NOT NULL, nullable 부모 정수 ID, 미션·종류·원본 ID에 대한 전체 유일 인덱스를 읽어 검사하도록 수정했다. `WITHOUT ROWID`와 컬럼 수준 `PRIMARY KEY DESC`처럼 자동 내부 키가 없는 변형도 거절한다. 서버 조회와 파이프라인이 같은 검증을 사용하며 분류 테이블에는 의존하지 않는다. 중간 스키마를 추측해 자동 복구하지 않는다.

수정 파일: `src/cholog_mcp/db.py`, `src/cholog_mcp/review_context.py`, `pipeline/schema.py`.

### P2: 재전환이 호출자의 미완료 트랜잭션을 커밋

이미 전환된 DB의 `migrate_schema`가 `create_schema`를 다시 호출했다. `executescript`가 호출자가 열어 둔 트랜잭션을 커밋하므로 이후 호출자 롤백으로 해당 변경을 취소하지 못했다.

명세와 재현 테스트를 먼저 추가했다. 이미 전환된 DB는 제약 검증 후 바로 반환하도록 수정했다. 구 DB 전환과 재전환 모두 호출자의 트랜잭션을 유지하며, 호출자 롤백은 미완료 데이터와 해당 트랜잭션 안의 전환을 되돌린다.

수정 파일: `pipeline/schema.py`.

### P2: 특수문자가 있는 DB 경로에서 읽기 전용 보장 실패

기존 `open_db`가 경로를 인코딩하지 않고 SQLite URI에 붙였다. 임시 `review #1.db`를 지정한 실험에서 `#` 뒤의 `mode=ro`가 URI fragment로 처리되어 다른 파일 `review `가 만들어졌다. `?`와 `%`가 있는 경로도 올바른 DB를 열지 못했다. 이는 기존 연결 코드에서 이어진 문제로, 이슈의 읽기 전용 요구사항을 확인하다 발견했다.

명세와 경로별 실패 테스트를 추가하고 `Path.resolve().as_uri()`로 경로를 인코딩했다. 지정한 파일에서 PR을 읽고, 쓰기는 실패하며, 다른 파일은 생기지 않는지 확인했다.

수정 파일: `src/cholog_mcp/db.py`.

## 페이지·커서 및 기존 도구 회귀 검토

- 댓글·본문과 diff 문자·대화 조각 제한, 큰 대화의 오프셋과 partial, 단일 초과 댓글, 빈 PR과 일반 대화, 동일 시각 순서를 명세와 대조했다.
- 페이지 분할 함수에 고정 seed 8로 구성한 혼합 합성 사례 300개를 추가 탐색했다. 여러 PR·빈 PR·여러 대화·50댓글 초과·0~24,001자 본문을 섞어 전체 순서, 누락·중복, 조각 오프셋과 제한을 검사했다. 추가 결함은 재현하지 못했다. 실제 대규모 자료 성능을 측정한 것은 아니다.
- 기존 커서 오류·범위/자료 변경·동시 DB 갱신 스냅샷·실제 HTTP 이어 읽기 테스트를 검토하고 전체 회귀에서 실행했다.
- 같은 원본을 재적재하면서 다른 미션이 내부 키를 점유해 내부 키 값이 달라져도 기존 커서의 이어 읽기 결과가 동일함을 새 테스트로 확인했다.
- 미션과 review/issue 종류의 원본 ID가 모두 겹치는 자료를 적재·분류·반복 재적재하는 테스트를 추가했다. 다른 미션의 댓글·분류 내부 키가 유지되고 원본 ID가 같은 댓글들의 주제가 섞이지 않으며, 기존 집계와 대표 리뷰 응답 전체가 유지됨을 확인했다. `verify`의 주제별 PR 집계도 확인했다.
- `feedback.py`, `tagger.py`, `verify.py`의 로직과 기존 도구의 입력·응답 계약은 변경하지 않았다.
